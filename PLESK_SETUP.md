# Инструкции по настройке на Plesk Shared Hosting

Это руководство поможет вам настроить SGEO Analytics на Plesk shared hosting с учетом всех ограничений.

## 🎯 Важно: Три режима сбора данных

Система поддерживает 3 режима работы для Plesk shared hosting:

### 1. ✅ Пакетный режим (РЕКОМЕНДУЕТСЯ)
**Преимущества:**
- Не превышает лимиты `max_execution_time`
- Работает прямо из браузера
- Показывает прогресс в реальном времени
- Безопасен для shared hosting

**Как использовать:**
1. Войдите в панель управления
2. Нажмите "🚀 Запустить сбор данных"
3. Выберите "OK" для пакетного режима
4. Не закрывайте страницу до завершения

### 2. 🔄 Cron-режим (АВТОМАТИЧЕСКИЙ)
**Преимущества:**
- Полностью автоматический
- Запускается по расписанию
- Не требует участия пользователя

**Настройка Cron в Plesk:**

1. Перейдите в **Tools & Settings** → **Scheduled Tasks** (или **Планировщик заданий**)

2. Создайте новое задание:
   ```
   Команда: /usr/bin/php /var/www/vhosts/maxico.kz/httpdocs/cli/collect-batch-cron.php
   Расписание: */15 * * * * (каждые 15 минут)
   ```

3. Скрипт автоматически:
   - Проверяет незавершенные запуски
   - Продолжает с того места, где остановился
   - Обрабатывает 2 топика за раз
   - Завершается когда все топики собраны

**Пример настройки:**
```
Minute: */15
Hour: *
Day: *
Month: *
Weekday: *
Command: /usr/bin/php /var/www/vhosts/maxico.kz/httpdocs/cli/collect-batch-cron.php
```

### 3. ⚠️ Полный режим (НЕ РЕКОМЕНДУЕТСЯ)
**Проблемы:**
- Может превысить `max_execution_time` (обычно 60-300 сек)
- Может зависнуть на shared hosting
- Не показывает прогресс

**Используйте только если:**
- У вас VPS/Dedicated сервер
- Увеличен `max_execution_time` до 600+ секунд

## 📋 Настройка базы данных

### Важно для Plesk:
- Используйте TCP/IP подключение вместо unix socket
- В файле `.env` установите:

```env
DB_HOST=127.0.0.1  # НЕ localhost!
DB_PORT=3306
DB_NAME=ваша_база
DB_USER=ваш_пользователь
DB_PASSWORD=ваш_пароль
```

### Проверка подключения:
```bash
php cli/test-db.php
```

## 🔧 Решение типичных проблем Plesk

### 1. Ошибка "open_basedir restriction"

**Проблема:** `Warning: file_exists(): open_basedir restriction in effect`

**Решение:**
- Уже исправлено в коде
- Используется TCP/IP вместо socket
- Сессии сохраняются в `/tmp`

### 2. Таймаут при сборе данных

**Проблема:** Сайт зависает при "Start Data Collection"

**Решения:**
1. Используйте **пакетный режим** (кнопка в панели)
2. Настройте **Cron** для автоматического сбора
3. Уменьшите `batch_size` в `collect-batch-cron.php`:
   ```php
   $batchSize = 1; // Было 2, стало 1
   ```

### 3. Ошибка "CSRF token"

**Проблема:** `{"error":"Invalid CSRF token"}`

**Решение:**
- Очистите cookies браузера
- Перезайдите в систему
- Проверьте что сессии работают: `<?php session_start(); echo session_id(); ?>`

## 📊 Мониторинг сбора данных

### Через веб-интерфейс:
1. Панель управления показывает текущий запуск
2. Прогресс обновляется автоматически
3. Статус: Выполняется / Завершен / Ошибка

### Через логи (SSH):
```bash
# Логи Apache/Nginx
tail -f /var/log/httpd/error_log
# или
tail -f /var/log/nginx/error.log

# Логи приложения
tail -f storage/logs/app.log
```

### Проверка через базу данных:
```sql
-- Последние запуски
SELECT * FROM monitoring_runs ORDER BY created_at DESC LIMIT 5;

-- Прогресс текущего запуска
SELECT id, status, completed_queries, total_queries,
       ROUND((completed_queries / total_queries) * 100, 1) as progress
FROM monitoring_runs
WHERE status = 'in_progress';
```

Система уже оптимизирована для Plesk:

- ✅ Сокращено количество API запросов на 95% (с ~2000 до ~100)
- ✅ Локальные алгоритмы scoring вместо дополнительных API вызовов

### Время выполнения:
- **Пакетный режим:** 2-3 минуты на 2 топика
- **Полный сбор:** 20-30 минут для всех 20 топиков

## 🔐 Безопасность

### 1. Защитите директорию /api:
В Plesk Panel → **Apache & nginx Settings** добавьте:
```apache
<Directory "/var/www/vhosts/maxico.kz/httpdocs/api">
    Require all denied
</Directory>
```

### 2. Защитите директорию /cli:
```apache
<Directory "/var/www/vhosts/maxico.kz/httpdocs/cli">
    Require all denied
</Directory>
```

### 3. Убедитесь что .env защищен:
```apache
<Files ".env">
    Require all denied
</Files>
```

## 📞 Поддержка

3. **Тестируйте подключение:**
