## 1. Криптографические компоненты

| Компонент | Алгоритм / Стандарт | Параметры |
|-----------|---------------------|-----------|
| Хеширование паролей | Bcrypt | cost factor 12 |
| TOTP (MFA) | HMAC-SHA1, RFC 6238 | period 30 сек, 6 цифр |
| Генерация токенов | `random_bytes()` | 256 бит (32 байта) энтропии |
| Транспорт | TLS 1.2+ | обязателен на продакшне |
| CSRF токены | `random_bytes(32)` + Base64 | per-session |

---

## 2. Управление сессиями

- **Тайм-аут бездействия:** 15 минут (`SESSION_IDLE = 900 сек`)
- **Максимальное время жизни:** 10 часов (`SESSION_LIFETIME = 36 000 сек`)
- После успешного входа вызывается `session_regenerate_id(true)` — защита от Session Fixation.
- Таймер обновляется при каждом запросе (`$_SESSION['last_activity']`).
- При превышении любого из лимитов сессия уничтожается (`session_destroy()`).

---

## 3. Политика паролей

- **Минимальная длина:** 18 символов.
- **Обязательная смена:** при первом входе, если флаг `users.force_password_change = TRUE`.
- **Редирект:** `/change-password` — пользователь не может перейти к другим страницам до смены пароля.
- Пароли никогда не попадают в audit_logs и другие логи.

---

## 4. Защита от атак

### Брутфорс / Credential Stuffing

- Подсчёт неудачных попыток за последние **15 минут** по IP **или** имени пользователя.
- При достижении **5 попыток** — вход блокируется, логируется `login_blocked`.
- Единое сообщение об ошибке `invalid_credentials` для всех сценариев (неверный логин, пароль, блокировка) — не раскрывает причину отказа.

### XSS (Cross-Site Scripting)

- Все пользовательские данные при выводе оборачиваются в `htmlspecialchars()`.
- Content-Security-Policy заголовок устанавливается в `.htaccess`.

### CSRF (Cross-Site Request Forgery)

- Все формы содержат скрытый токен `csrf_token`.
- Каждый POST-запрос проверяется через `verify_csrf_token()`.

### SQL Injection

- Все запросы к БД используют PDO Prepared Statements.
- Прямая конкатенация пользовательских данных в SQL строго запрещена.

## 5. Аудит

Логирование выполняется в таблицу `audit_logs` через `AuditService`.

### Что логируется

| Событие | Метод |
|---------|-------|
| Успешный вход | `logLogin` |
| Выход | `logLogout` |
| Неудачная попытка входа | `logLoginFailed` |
| Блокировка входа | `logLoginBlocked` |
| Смена пароля | `logPasswordChanged` |
| Генерация отчёта | `logReportGenerated` |
| Сбор данных | `logDataCollection` |
| Просмотр топика | `logTopicViewed` |
| Экспорт отчёта | `logReportExported` |
| Изменение настроек | `logSettingsChanged` |

### Что НЕ логируется

- Пароли (ни в открытом виде, ни хешированные)
- API-ключи и токены доступа
- Содержимое тела HTTP-запроса целиком
- Персональные данные, не относящиеся к событию

## 7. MFA (Многофакторная аутентификация)

- **Алгоритм:** TOTP по RFC 6238 (Time-based One-Time Password).
- **Приложения:** совместимо с Google Authenticator, Authy, любым RFC 6238 клиентом.
- **Окно допуска:** ±1 период (30 сек) для компенсации рассинхронизации часов.
- **Обязательна для ролей:** `admin`, `manager`.
- **Резервные коды:** 8 одноразовых кодов генерируются при подключении MFA. После использования код удаляется.
- **Хранение:** секрет хранится в таблице `mfa_secrets`, backup_codes как JSONB-массив.
- **Поток:** после проверки пароля, если MFA включена → `$_SESSION['mfa_pending_user_id']` → редирект на `/login/mfa`.
